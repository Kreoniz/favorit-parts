# Design prototype

Одноразовый макет для выбора компоновки. Здесь нет React, Redux и настоящих API-запросов: это будет отдельная реализация после согласования дизайна. Данные и цены вымышлены.

```sh
mise exec -- bun run prototype
```

Открыть <http://127.0.0.1:5173/?variant=A>. Также HTML можно открыть напрямую в браузере.

- `?variant=A` — последовательный поиск: артикул, производители, таблица.
- `?variant=B` — рабочая область: производители слева, предложения справа.
- `?variant=C` — карточки деталей с предложениями по складам внутри.

Переключение вариантов — стрелки на плавающей панели или клавиши ← →. Меню рядом позволяет посмотреть загрузку, выбор производителя, пустой ответ и ошибку. Пример артикула: `0189`.

Ветка `prototype/design` сохраняет весь макет для истории. После ревью в `main` попадёт выбранная компоновка, реализованная заново на целевом стеке.

## Проверенные факты API

2026-11-16: GET-запросы с ключом из примеров PDF работают по HTTPS на `https://api.favorit-parts.ru/hs/hsprice/`. Ответы содержат `Access-Control-Allow-Origin: *`, в том числе при `Origin: https://example.github.io`. Для простого GET прокси не требуется; GitHub Pages подходит для размещения клиента. Сам браузерный fetch с GitHub Pages пока не проверялся.

- Первый этап: `key`, `number`; бренды берутся из `goods[].brand`.
- Второй этап: дополнительно `brand`, `analogues=on`; аналоги вложены в `goods[].analogues`.
- Цена и остаток берутся из `warehouses[].price` и `warehouses[].stock`. Верхнее `goods[].price` документацией запрещено использовать.
- Пустые `warehouses` означают отсутствие предложений; отсутствие цены не равно нулю.

Источник: <https://lk.favorit-parts.ru/static/wsprice.pdf>; проверка публичного ключа и заголовков живыми HTTP/HTTPS запросами 2026-11-16.
