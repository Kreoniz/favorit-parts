# Варианты нового дизайна — 16.11.2026

Исследование выполнено ровно двумя запрошенными субагентами: `gpt-6.1-terra` с `reasoningEffort=xhigh` и `gpt-6.1-sol` с `reasoningEffort=xhigh`. Обе модели и настройки подтверждены результатами задач. Агенты независимо читали текущий код, смотрели скриншоты и изучали онлайн-первоисточники. Отчёты: `terra.md` и `sol.md`.

## Что требует задание

React, Redux, JavaScript без TypeScript; Bootstrap желателен, стилизация свободная. Артикул → производители → выбор бренда → предложения и аналоги. Название/бренд, цена и остаток обязательны. Нужны состояния загрузки, пустых ответов и ошибок. Шапка с логотипом, «Демо-доступ», декоративные подписи и прежняя зелёная палитра в задании отсутствуют.

## В чём агенты согласны

- Удалить декоративный хедер, бейдж доступа, инициалы бренда и повторяющиеся инструкции.
- Сделать нормальную типографику: 16 px для основного текста и 14 px для вторичного.
- Использовать штатные нейтральные цвета Bootstrap и один синий акцент. Зелёный оставить для наличия, красный — для ошибки.
- Поддержать светлую, тёмную и системную темы через `data-bs-theme`.
- На телефоне показывать цену, остаток и склад с явными подписями, без горизонтальной прокрутки.
- Не подменять отсутствие цены нулём; аналоги без складских предложений оставлять видимыми.

## Различия

**Terra — рабочая область.** Поле и список брендов слева, таблица справа. Хорошо подходит для частого переключения производителей: все варианты видны одновременно. За это приходится платить шириной таблицы; длинные названия и артикулы чаще переносятся.

**Sol — форма сверху.** Артикул и нативный select производителя над таблицей во всю ширину. Список не занимает место после выбора, на телефоне открывается системный контрол. Это проще и компактнее для одного сценария поиска; для просмотра всех брендов нужно открывать select.

Моя рекомендация — **Sol**: у приложения одна основная задача, таблица содержит самые важные данные. Сохранить от Terra заметное состояние выбранного бренда и понятные состояния загрузки. Если приоритетом станет частое сравнение брендов, вариант Terra остаётся разумным.

## Реализация на Bootstrap

Компоновка: `container`, `row`, `col-*`, spacing/flex utilities. Поля: `form-label`, `form-control`, `form-select`. Бренды в Terra: `list-group-item-action`, `active`, `aria-pressed`. Результаты: `table`, `align-middle`, `text-end`, `fw-semibold`, мобильный `list-group`. Загрузка: `spinner-border`; ошибки: `alert alert-danger`, повтор — `btn btn-primary`. Фоны: `bg-body-tertiary`; текст: `text-body-secondary` и semantic emphasis-классы.

Небольшой собственный CSS нужен для табличных цифр, переноса длинных обозначений, контраста полей, размеров контролов и мобильного представления. Перерисовывать всю библиотеку вручную не требуется. Процент «на Bootstrap» не является критерием задания: важнее простота и читаемость.

## Визуализация

`redesign.html` — автономный интерактивный макет с настоящим CSS Bootstrap 5.3.9. `?variant=terra` и `?variant=sol`; варианты переключаются стрелками снизу и клавишами ← →. Тема выбирается в верхней строке, сценарии — на отдельной панели ревью. Данные вымышлены и одинаковы в обоих вариантах. Переключатель темы в макете хранит выбор только в памяти; в рабочем приложении нужно сохранять предпочтение и применять его до первого рендера.

Для совместимости с подгоняющим высоту inline-просмотром неиспользуемые CSS-утилиты с единицами высоты viewport заменены фиксированными значениями. Используемые компоненты, сетка и typography Bootstrap сохранены. Макет не использует реальный API и не меняет приложение на localhost.
