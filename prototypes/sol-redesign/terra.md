## Оценка и компоновка

На скриншотах текущий сценарий понятен и таблица уже показывает аналоги без предложений. Однако тонкая светло-зелёная палитра, множество рамок, иконок и подписей 9–12 px снижают читабельность. На мобильном результаты начинаются только после высокой вводной части, а данные склада разнесены по строкам с большими промежутками.

Desktop: контейнер до 1200 px, верхняя строка 48–56 px, ниже сетка примерно 300–320 px и оставшаяся ширина, промежуток 24 px. Слева видимый `label` и поле артикула, под ним список производителей с явным выбранным состоянием. Справа заголовок «Предложения и аналоги · артикул / бренд», затем таблица: деталь и производитель, склад, остаток, цена. Числа выровнять вправо; исходную деталь пометить текстом «Искомая», остальные — «Аналог». Одна строка на склад, с понятной повторной идентификацией детали.

Mobile: одна колонка, поле на всю ширину, список брендов вертикально; длинный список ограничить по высоте с доступной прокруткой, не сворачивая его автоматически после выбора. Затем результаты. Использовать отдельное адаптивное представление данных: имя, производитель и артикул; ниже по каждому складу подписанные склад, остаток и цена. Это увеличивает вертикальную длину и ухудшает сравнение цен между позициями, но устраняет горизонтальный скролл. Проверить на длинных названиях и с экранным диктором; не дублировать одновременно две доступные версии.

## Палитра и реализация

Контраст рассчитан по относительной яркости WCAG для указанных непрозрачных пар; число — отношение текста к фону. Границы отделяют поверхности и не используются как единственный признак состояния.

| Назначение | Светлая | Тёмная |
|---|---|---|
| Фон страницы / поверхность | `#F8F9FA` / `#FFFFFF` | `#212529` / `#2B3035` |
| Основной текст на поверхности | `#212529` / `#FFFFFF`: 15,43:1 | `#DEE2E6` / `#2B3035`: 10,23:1 |
| Вторичный текст на фоне страницы | `#495057` / `#F8F9FA`: 7,76:1 | `#ADB5BD` / `#212529`: 7,43:1 |
| Ссылка на фоне страницы | `#084298` / `#F8F9FA`: 8,88:1 | `#6EA8FE` / `#212529`: 6,39:1 |
| Выбранный бренд: текст / фон | `#FFFFFF` / `#084298`: 9,36:1 | `#FFFFFF` / `#084298`: 9,36:1 |
| Разделители | `#DEE2E6` | `#495057` |

Текст и акцент нельзя переносить на произвольные фоны. Не полагаться только на цвет выбора: добавить галочку и `aria-pressed`. Фокус — отчётливый `:focus-visible`, проверенный в обеих темах.

Использовать Bootstrap `container`, `row`, `col-lg-3/9` или близкую сетку, `form-label`, `form-control`, `list-group` с кнопками, `table`, `text-end`, `alert`, `spinner-border`, `btn` и `form-select` для темы. Минимум CSS: переменные цветов по `[data-bs-theme]`, ширина контейнера, плотность таблицы, адаптивные блоки на mobile, перенос длинных артикулов и табличные цифры. Проверить состояния hover/focus/active и цвета компонентов отдельно: переопределение одних глобальных переменных не гарантирует их согласованности.

## Поведение и состояния

Ввод сохраняется; поиск производителей запускается автоматически после небольшой задержки. При изменении артикула сбросить бренд и устаревшие результаты; ответ старого запроса не должен подменить новый. Пока производители загружаются — текст и spinner; при пустом результате — «Производители не найдены. Проверьте артикул». При выборе бренда запрашивать артикул, бренд и `analogues=on`; загрузку предложений показывать отдельно. Ошибки сети и API описывать понятным текстом в соответствующей области с «Повторить», без сырых технических деталей. Объявлять состояние через `role=status`, ошибку через `role=alert`, не переносить фокус при каждом обновлении.

Цена берётся только из `warehouses[].price`, остаток — из `warehouses[].stock`; не подменять отсутствующие значения нулём. Аналог без складских предложений остаётся в списке с ценой «—» и текстом «Нет предложений». Несколько складов показывать раздельно. Прочерк означает отсутствие данных, а не бесплатную деталь.

Тема: доступный `select` «Тема: Системная / Светлая / Тёмная». Сохранить выбор локально; системный режим отслеживает `prefers-color-scheme`, явный выбор имеет приоритет. Устанавливать `data-bs-theme` на `html` до отрисовки, чтобы уменьшить вспышку. Системная тема по умолчанию уважает настройку устройства; принудительная тёмная тема потребовала бы отдельного решения пользователя.

## Основания и ограничения

- [Bootstrap: Color modes](https://getbootstrap.com/docs/5.3/customize/color-modes/) описывает `data-bs-theme` и пример переключателя; отсюда предложенная реализация без новой библиотеки.
- [W3C WCAG 2.2: Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) требует для обычного текста минимум 4,5:1; это основание расчётов, а не проверка всех состояний интерфейса.
- [USWDS: Search](https://designsystem.digital.gov/components/search/) рекомендует сохранять запрос в поле и достаточно широкое поле; применено к артикулу. Автоматический поиск — отдельное требование этого проекта.
- [GOV.UK: Table](https://design-system.service.gov.uk/components/table/) рекомендует заголовки, `caption` и выравнивание чисел справа для сравнения; применено к desktop-таблице.
- [GOV.UK: Layout](https://design-system.service.gov.uk/styles/layout/) предлагает начинать с одной колонки на малом экране; применено к мобильной компоновке.

Предложение основано на коде и скриншотах, без проверки пользователями. Цвета состояний, масштабирование, клавиатурную навигацию и мобильное представление нужно проверить после реализации.
