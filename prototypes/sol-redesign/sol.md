Независимый дизайн-ревью Sol · 16.11.2026

Изучены `App.jsx`, `styles.css`, компоненты, преобразование предложений, README, desktop/mobile-скриншоты и официальные онлайн-источники. Это самостоятельное предложение; пользовательское тестирование не проводилось.

Наблюдения по текущему интерфейсу: боковая колонка сужает результаты, несколько заголовков повторяют назначение страницы, важные подписи имеют размер 9–12 px. В CSS зафиксированы светлая схема и белые поверхности. Простое добавление переключателя темы оставит часть интерфейса светлой.

Предлагаю последовательную рабочую страницу «Поиск запчастей»: нейтральные поверхности, один синий акцент, заметные цены и ясный следующий шаг. Пять конкретных тезисов:

1. Убрать отдельную шапку с логотипом, «Демо-доступ», надписи «Каталог запчастей», «От артикула к предложениям», декоративные инициалы бренда и повторные инструкции. Начало страницы — одна компактная строка: `h1.fs-4.mb-0` и выбор темы. Панель навигации здесь не требуется. Информация о ключе нужна только при соответствующей ошибке.

2. На desktop отказаться от master-detail B. В `.container.py-4` разместить форму `.row.g-3` с двумя `.col-12.col-md-6`: «Артикул» и «Производитель». Ниже — результаты на всю ширину. Использовать `.form-label`, `.form-control`, нативный `.form-select`, `.form-text`; подписи сверху, пример `0189` под полем, связанный через `aria-describedby`. Подсказка «Производители появятся автоматически» объясняет поведение. Список брендов сортируется; начальное значение — «Выберите производителя», даже если найден один. Отдельная кнопка поиска не нужна.

3. На mobile оба поля идут вертикально; длинный список производителей открывается штатным системным select и не отодвигает результаты. От 768 px — `.table.align-middle.mb-0`, колонки «Деталь», «Склад», «Остаток», «Цена». Название получает около половины ширины; бренд и артикул — второй строкой. Числа и заголовки числовых колонок — `.text-end`, цена — `.fw-semibold.text-nowrap`. Ниже 768 px — `.list-group.list-group-flush`: название, бренд/артикул, затем строки «Склад», «Остаток», «Цена» с явными подписями. Две презентации одних данных переключаются `.d-none.d-md-block` / `.d-md-none`; запросы общие. Без горизонтальной прокрутки и раскрывающихся карточек. Основной текст 16 px, вторичный 14 px, элементы управления минимум 44 px.

4. Сохранить автоматический поиск через 400 мс. Пока артикул пуст, показать короткую инструкцию под формой; производителя отключить с текстом «Сначала введите артикул». При загрузке — `.spinner-border.spinner-border-sm` и «Ищем производителей…» либо «Получаем предложения…», `role="status"`, `aria-busy` у обновляемой области. Пустые состояния различать: «Производители не найдены», «Детали не найдены», «Детали найдены, складских предложений нет». Ошибки сети, тайм-аута, лимита и API — понятным текстом рядом с соответствующим этапом, `.alert.alert-danger`, `role="alert"`, `.btn.btn-primary` «Повторить». Ввод сохраняется. Смена артикула сразу очищает бренд и результаты; смена бренда убирает прежние предложения. Фокус остаётся на использованном контроле, результат объявляется кратким live-сообщением.

5. Каждая строка desktop — конкретное складское предложение. Цена строго из `warehouses[].price`, остаток из `warehouses[].stock`; значения разных складов не объединять. Формат `1 040,60 ₽`, `4 шт.`; `0,00 ₽`, `0 шт.`, «Не указан» и отсутствие предложения различаются. Аналог без складов сохраняется: цена «—», остаток «Нет предложений»; отсутствующая цена существующего предложения также «—». Запрошенная деталь первой, далее аналоги; тип подписан текстом. Цвет дополняет подпись. Цены остаются обычным контрастным текстом, зелёный используется только для положительного остатка. Счётчик «3 детали · 1 предложение» помогает понять результат.

Палитра основана на штатных нейтральных и semantic-цветах Bootstrap. Единственное изменение текстовых токенов — непрозрачный вторичный цвет для предсказуемого контраста.

| --- | --- | --- |

Контраст рассчитан скриптом по относительной яркости sRGB: основной текст на странице/панели — минимум 14,63:1 light и 10,23:1 dark; вторичный — 7,76:1 / 6,42:1; акцентная пара — 10,28:1 / 7,45:1; наличие — 10,35:1 / 7,67:1; ошибка — 10,22:1 / 7,15:1. Белый на кнопке — 4,500783:1. Синий #0D6EFD на #F8F9FA даёт 4,27:1: для обычного текста на панели применять `.text-primary-emphasis`. Контуры полей относительно обеих поверхностей — минимум 4,45:1 / 6,42:1; тонкие разделители служат декорацией.

Тему выбирать подписанным `.form-select.w-auto`: «Авто / Светлая / Тёмная». По умолчанию «Авто» следует `prefers-color-scheme`; сохранять выбор в `localStorage`, реагировать на смену системной темы только в auto. На `<html>` ставить вычисленное `data-bs-theme="light|dark"` до первого отображения.

Собственный CSS: два набора вторичных токенов, контуры полей, непрозрачный `:focus-visible` в цвете системной ссылки, минимум высоты контролов, `font-variant-numeric: tabular-nums`, перенос длинных обозначений. Остальное — utilities, `.bg-body-tertiary`, `.text-body-secondary`, `.rounded`, `.border`, `.alert-danger`, `.text-success-emphasis.bg-success-subtle`. Заголовкам ячеек задать `--bs-table-bg: var(--bs-tertiary-bg)`; сохранить `caption` и `scope`. Не закреплять `.table-light`/`.table-dark`: они мешают автоматической смене оформления.

Факты первоисточников и влияние на решение:

- [Bootstrap Color modes](https://getbootstrap.com/docs/5.3/customize/color-modes/): режимы, CSS-переменные, системная тема и ранняя установка атрибута; основа light/dark/auto.
- [Bootstrap Tables](https://getbootstrap.com/docs/5.3/content/tables/): responsive означает горизонтальную прокрутку, цветовые варианты имеют ограничения адаптации; поэтому мобильный список и обычная `.table`.
- [GOV.UK Text input](https://design-system.service.gov.uk/components/text-input/): видимые подписи сверху и постоянные подсказки; пример вынесен из placeholder.
- [Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines): таблице рекомендуют достаточную ширину; основание убрать sidebar.
- [W3C Contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): порог 4,5:1 для обычного текста и формула яркости; основание расчётов палитры.
